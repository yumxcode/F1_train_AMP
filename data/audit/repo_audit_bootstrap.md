## 1. Robot identity (URDF/MJCF/meshes)

- Repo remote: `git@github.com:yumxcode/F1_train_AMP.git`. "F1" is the **project
  codename**; the physical robot defined in `resources/robots/x1/` is **AgiBot X1**
  (README + copyright "AgiBot Inc." + MJCF `xyber_x1`).
- URDF `resources/robots/x1/urdf/x1.urdf`: 57 joints, of which exactly **12 are
  revolute (actuated)** — all leg DOF, 6 per leg:
  `left/right_{hip_pitch,hip_roll,hip_yaw,knee_pitch,ankle_pitch,ankle_roll}_joint`.
  Upper body (waist, lumber, shoulders, elbows, wrists, toes) are all **fixed**
  joints → this is a legs-only locomotion model.
- Actuated joint ORDER in the env == URDF dof_names == AMP `X1_JOINT_NAMES`
  (`humanoid/algo/amp/motion_lib.py`). No foreign-robot indices, no dict-order
  dependence. Verified consistent across stand cfg, amp cfg, motion_lib, amp env.
- Default pose / limits: `X1_DEFAULT_DOF_POS` and `X1_JOINT_LIMITS` in motion_lib
  mirror `cfg.init_state.default_joint_angles` and `cfg.safety.manual_joint_clip`.
- Conclusion on identity: the real F1/X1 model is **present and self-consistent**.
  This is an **X1-naming legacy**, NOT a blocking precondition — the model, joints
  and the reference-motion source (raw SMPL-X walk in `data/`) are all defined and
  consistent.

## 2. AMP closed-loop code — verified genuine (not a dummy/rename)

Files under `humanoid/algo/amp/` and `humanoid/envs/x1/x1_amp_*`:

- `motion_lib.py`: AMP feature = `[base_lin_vel(3), base_ang_vel(3),
  projected_gravity(3), dof_pos_rel(12), dof_vel(12), foot_contact(2)]` →
  **AMP_OBS_DIM = 35**. Expert builder (`build_amp_obs_numpy`) is numpy/headless;
  velocities via finite-diff (standard for mocap). Resample to 100 Hz, joint-range
  + finiteness checks. **Headless-verified**: loads synthetic clip → 300 frames→299
  AMP rows, finite, in-range, base_lin_vel≈0.4 m/s forward.
- `x1_amp_env.py`: policy builder `compute_amp_obs` mirrors the expert layout in
  torch (base-frame lin/ang vel via `quat_rotate_inverse`, dof_pos_rel vs the same
  default, sim dof_vel, contact>5N). Dim/order/frame/units match; velocity source
  differs (sim vs finite-diff) which is the **conventional AMP** practice.
- `discriminator.py`: state-only single-logit D; standard softplus GAN loss +
  R1 gradient penalty on policy samples; style reward
  `r = clamp(1 - 0.25*(ema(D(e)) - D(p)), 0, 2)` (correct sign; prior sign bug
  documented as fixed).
- `replay_buffer.py`: circular policy-feature buffer; intentionally not persisted
  (no learned state, refills per iteration; avoids all-zero-sample corruption).
- `amp_on_policy_runner.py`: discriminator trained once/iter, **style reward added
  BEFORE `process_env_step` so GAE sees it**; checkpoint save/load include disc +
  disc-optimizer + expert-logit-EMA (resume-safe); construction asserts
  env amp_obs dim == disc input dim (schema gate).

Registration: `humanoid/envs/__init__.py` registers `x1_amp` (AMPOnPolicyRunner) AND
keeps `x1_dh_stand` (DHOnPolicyRunner, plain PPO) unchanged → AMP is independent, not
a rename.

## 6. Bug found & fixed this iteration (amp_conversion)

- `smoke_amp.py` did NOT override `train_cfg.amp.expert_clip_paths`, which points at
  the Gate-B retargeted clip (absent on a fresh checkout after the reset). Re-running
  the Gate-A smoke on the current HEAD would therefore have raised FileNotFoundError
  at `AMPOnPolicyRunner` construction.
- Fix: `smoke_amp.py` now regenerates the deterministic synthetic Gate-A expert
  (`gen_smoke_expert.main`) if absent and overrides `expert_clip_paths` to it. This
  keeps the Gate-A bounded smoke **self-contained and reproducible** without depending
  on Gate-B output (correct phase boundary). py_compile + AST parse OK.
